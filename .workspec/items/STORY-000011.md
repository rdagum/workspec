# Summary

Files change underneath the app (git pull, branch checkout, an agent editing) and today the app silently overwrites them. Detect external changes and refuse to clobber them.

# Business Context

Git-native means the working tree is shared with Git and with AI agents. Overwriting their changes is the worst failure mode a file-based tracker can have.

# Technical Context

The File System Access API has no watcher; `file.lastModified` polling and a focus-time listing comparison are sufficient. Optimistic concurrency compares the on-disk text to `record.raw` immediately before a write.

# Requirements

- Polling of the open item and focus-time repository check.
- Pre-write comparison in `saveItem` and `moveItem`.
- Banner UI with Reload / Keep mine.
- State-preserving reload.

# Implementation Notes

Depends on STORY-000002 for record versioning so a reload can rebind the editor safely.

# Risks

Polling cost is negligible for one file but must not extend to all items; the directory check on focus only compares names and counts.
