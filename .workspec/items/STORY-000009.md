# Summary

Every session starts with the directory picker. Persist directory handles and offer a recent-repositories list so reopening is a single permission click.

# Business Context

This is the most repetitive step in every session and the largest day-to-day UX win available for the cost.

# Technical Context

`FileSystemDirectoryHandle` objects are structured-cloneable and can be stored in IndexedDB; the persistence layer lands in STORY-000006. This story adds the UI and the reopen flow.

# Requirements

- Recent list in the empty state and in the topbar open-button menu.
- Permission re-request and graceful handling of revoked or missing handles.
- Optional auto-reopen preference stored alongside the theme preference.

# Implementation Notes

Keep the IndexedDB code in `core/filesystem.js` (or a small `core/recent.js`) so `app.js` stays wiring-only (see STORY-000005).

# Risks

Permission prompts differ between file:// and http origins; test both.
