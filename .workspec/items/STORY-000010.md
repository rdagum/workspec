# Summary

Relationships are the specification's core idea (SPEC.md section 10) but the UI only renders the parent breadcrumb. Make relationships navigable, validated and visible on the board.

# Business Context

Engineers and agents both need to see what blocks what without opening files one by one.

# Technical Context

Relationship fields are plain text arrays in the editor today. The model already indexes items by path; add an index by ID (also needed by the ID collision work) to resolve references cheaply.

# Requirements

- Chips and picker in the editor.
- Reference validation in `validateItem` with an ID index from `loadRepository`.
- Blocked badge and child count on cards.
- Swimlane grouping by parent.

# Implementation Notes

Chip rendering can reuse the existing pill styles. Keep swimlanes as a render-only concern in `BoardView`; the store keeps returning columns.

# Risks

Swimlanes multiply DOM nodes; coordinate with STORY-000004 rendering work.
