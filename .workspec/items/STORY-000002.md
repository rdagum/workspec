# Summary

The editor keeps a private working copy that is only refreshed when a different item is opened. Any other mutation of the same record is invisible to it, and navigation discards the copy even when the flush-save failed. Give the open record one source of truth.

# Business Context

Two confirmed lost-update paths: dragging the open card then saving writes the old status back; a failed save on navigation (or Escape on invalid YAML) silently throws edits away. Both violate "never silently fail".

# Technical Context

`ui/editor.js:68-79` binds on path change only. `state/store.js:169` mutates `record.meta.status` without telling the editor. `app.js:23-29` flushes via `save()` which swallows errors and returns nothing, then proceeds to `store.open()`.

# Requirements

- Add `record.version`; `_bind` keys on `path + version`.
- Merge strategy for dirty working copies (field-level, with a notice).
- `save()` returns a boolean; all navigation call sites honour it.
- Save / Discard / Cancel prompt when leaving with a failed or invalid buffer.
- Remove the dead `state.dirty` (`state/store.js:28`) or make it authoritative.

# Implementation Notes

Consider a `Revert` button in the editor header while here; there is currently no way to discard edits without reloading.

# Risks

Merging into a dirty working copy must never overwrite fields the user is actively typing in; only apply the externally changed keys.
