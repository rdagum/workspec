# Summary

Add the pure "who belongs to this epic" logic the epic filter and the AI-usage roll-up both need: walk an item's `parent` chain, safely, and derive an epic's members and progress.

# Business Context

Tasks usually hang off stories, not epics. A filter that matches only `parent == EPIC-ID` would drop them silently, and the user would think the epic had less work left than it does.

# Technical Context

`SPEC.md` §18.2 already defines an epic roll-up as "the items that reach it through `parent`"; nothing in the code walks that chain yet. `core/model.js` holds the other pure model helpers (`buildColumns`, `sortItems`, `distinctValues`) and is loaded in Node by `test/load.js`. Items are keyed by path (`items/<ID>.md`) in `model.items`, as the card breadcrumb in `ui/board.js` already assumes.

# Requirements

- Pure functions over the model; no store or DOM.
- Never throw on bad data: missing parents and cycles are reported elsewhere (or not at all), not here.
- Compute each item's chain in one pass per call; the board re-renders on every store change, so avoid quadratic work on large repositories (for example, build a member index once per model and reuse it).

# Implementation Notes

Decide in the pull request whether the index is cached on the model object or rebuilt per render, and say why. STORY-001003's epic roll-up should call these helpers rather than add its own walk.

# Implementation Notes (decisions taken, 2026-09-29)

`core/model.js` exports `isEpic`, `indexById`, `parentChain`, `epicIndex`, `idList`, `doneColumn` and `epicProgress`. `epicIndex(model)` does one parent walk per item and returns the epics, each epic's members, each item's epics, the "no epic" items, and a `blockedBy` map (the reverse of every `blocks` list, used by STORY-001007). The index is **not** cached on the model object: records are mutated in place by saves and moves, so a model-level cache would need invalidation hooks in every mutation. Instead `Store.epicIndex()` caches it per store version: the version bumps on every `emit()` and the cache is dropped in `set()`, so the index is built at most once per render. Tests: `test/epic.test.js`.
