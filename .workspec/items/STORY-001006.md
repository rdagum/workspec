# Summary

Add the Epics list to the sidebar and the `epic` filter to the store, so clicking an epic narrows the board to that epic and all of its work.

# Business Context

The user wants to finish epics as projects: see what is left in one epic, move its items across the columns, and close the epic when everything is Done, without the other epics' cards in the way.

# Technical Context

Filters live in `state/store.js` (`emptyFilters`, `filteredItems`, `setFilter`, `clearFilters`); `ui/sidebar.js` renders them as `<select>`s. This filter is a list instead, because it carries progress and is meant to stay visible; reuse the `.context-link` button style and its `.active` state. Membership and progress come from the STORY-001005 helpers. Drag and drop is unaffected: it patches `status:` on the dragged card whatever filter is active.

# Requirements

- One more key in `emptyFilters()`; no parallel filter state.
- No arithmetic in `ui/`.
- Clearing a stale focus happens in the store after a model load or save, not in the view.

# Implementation Notes

The reference layout is in the design document, section 2. The rejected alternative (an Epics column left of Backlog) and why it was rejected are in section 1.1; do not reintroduce drop-to-set-parent.

# Implementation Notes (decisions taken, 2026-09-29)

`filters.epic` holds an epic ID or `NO_EPIC` (`'(none)'`, exported from `state/store.js`). `Store.epicList()` feeds the sidebar; `toggleEpicFocus`, `setShowDoneEpics` and `focusedEpicId` are the other entry points. The stale-focus prune runs in `Store.set()`, which every load, save, create and delete goes through; a focus on an unknown ID is also ignored by the filter, so the board is never emptied by it. The Epics section sits between Search and Filter so the project list is visible without scrolling. The focused epic stays in the list even when it is done and "Show done" is off.
