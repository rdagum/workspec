# Summary

Make AI usage visible where people look: a cost chip on cards, a subtotal per column, an "AI usage" section in the editor that replaces the read-only YAML textarea for the `agent:` namespace, and totals for the filtered items in the sidebar. PROMPT.md 4.10 states the requirements; this story implements them.

# Business Context

Recording usage is only worth doing if it changes decisions. The board is where an item's cost, its budget and the team's spend by column or by agent should be obvious without opening files or running a tool.

# Technical Context

Cards render in `ui/board.js` `_renderCard` with a `.card-meta` badge row that already carries priority, assignee and label pills; the chip is one more pill. The editor builds its form from the data, not a schema (`ui/editor.js` `_field`), and today a nested object becomes a read-only YAML textarea; the new section is one more branch of that chain, keyed on the `agent` key, and STORY-000007 can fold it into the schema later. The sidebar already computes "N of M shown" from `store.filteredItems()`; the usage section reads the same list. The editor deep-clones `meta` when it binds, so a run appended by the CLI while the item is open is overwritten on the next save — that is STORY-000011's change-on-disk problem and is not solved here, but the section should not make it worse.

# Requirements

- Chip, column subtotal, editor section, sidebar section, demo data, README.
- No arithmetic in `ui/`; formatting only.
- Decimal budgets stay strings (the existing `coerce()` already leaves decimals alone).

# Implementation Notes

The design gate of the daily routine needs a reference for UI that is not an existing pattern; the text layout in the design document is that reference. Reuse the pill styles for the chip and the existing section styling for the editor block. Keep the period selector in the store so the sidebar and a future palette can share it.

# Risks

The runs table can get long on an epic; cap the visible rows and show "n more" rather than rendering hundreds of rows in the floating detail view.

# Implementation Notes (decisions taken, 2026-09-14)

The card chip landed on its own ahead of the rest: `.pill.cost` in the `.card-meta` row shows the list-price cost when every run is priced, else `<tokens> tok`, turns red with `.over-budget`, and carries the usage summary as its tooltip. `settings.card_fields` hides it when the list is present and omits `cost` (both `board.yaml` files now list it); the other entries of that list stay unhonoured. The demo repository has `config/ai.yaml` with fictional models and runs on STORY-000002 (over budget), STORY-000003 (unpriced) and BUG-000002 (recorded cost). Still open for this story: the column subtotal, the editor's AI usage section, the sidebar totals with the period selector, and the store-level tests.
