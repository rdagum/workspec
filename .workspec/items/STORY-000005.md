# Summary

`app.js` (428 lines) owns repository lifecycle, two dialogs, the context overlay, theme, scroll preservation, overlay/toast plumbing and keyboard handling. The create-item flow also contains pure domain rules that belong in `core`. Split it along those lines.

# Business Context

Smaller, single-purpose files are easier to review and to reuse from a CLI or an agent (item creation in particular).

# Technical Context

Target layout from docs/REVIEW-2026-09.md section 1.3:

```
app.js            wiring only
app/theme.js      storedTheme / setTheme / applyTheme / toggleTheme
ui/overlay.js     showOverlay / closeOverlay / showToast
ui/dialogs.js     openCreateDialog, confirmDelete
core/factory.js   createItemMeta(template, title, model, local) -> { meta, body }
```

# Requirements

- Extract modules keeping the `window.WS` global-namespace pattern.
- Move `createItem` domain logic (`app.js:195-244`) into `core/factory.js`.
- While moving it, validate the template `status` against `model.workflow` (`app.js:214`) and format the local date (`app.js:199`).

# Implementation Notes

Pure refactor plus two small fixes; keep the diff reviewable by doing the extraction in one commit and the fixes in another.

# Risks

Script load order in `index.html` is manual; a wrong order fails at startup. Add a startup assertion that required `WS` members exist.
