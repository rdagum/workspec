# Summary

The routine's own recorder, `.claude/skills/workspec-daily-work/scripts/record_usage.py`, adds the whole `cache_creation_input_tokens` of every response to `cache_write_tokens`, the five-minute kind (line 98). Claude Code writes its prompt cache with the one-hour TTL, which `config/ai.yaml` prices at 2× input against 1.25× for five minutes. Every run it records is therefore under-costed.

# Steps to Reproduce

1. `node tools/record-usage.js EPIC-001001 --from-transcript=16a4f3bd-945d-43c3-b8d2-ae9f5888b6e1 --dry-run` reports `cache_write_tokens: 0`, `cache_write_1h_tokens: 119920`.
2. Run `record_usage.py` on any item with `--session 16a4f3bd-945d-43c3-b8d2-ae9f5888b6e1 --dry-run` (or read line 98).

# Expected Behavior

119,920 one-hour cache-write tokens, priced at $20/MTok for claude-fable-5-1.

# Actual Behavior

119,920 five-minute cache-write tokens, priced at $12.50/MTok: about $0.90 too low on that one session.

# Technical Context

Found while adopting usage tracking (STORY-001004). In this repository the routine now records with `tools/record-usage.js`, which splits the two kinds (`tools/transcript.js`), so this affects only repositories without that tool, where `record_usage.py` is the fallback.

# Implementation Notes

Read the split from `message.usage.cache_creation` as `tools/transcript.js` does, and add `cache_write_1h_tokens` to `RUN_KEYS`.
