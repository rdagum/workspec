# Summary

There are no automated tests for a codebase whose most delicate parts (the YAML engine, the parser, ID rules) are pure functions. Add a harness using Node's built-in test runner so those modules are covered without introducing a build step or a dependency.

# Business Context

Every data-safety fix in A1 and A2 needs a regression test, and future contributors need a fast way to prove they have not broken round-tripping.

# Technical Context

Each module is an IIFE that receives `window.WS`, so it can be loaded in Node with a three-line shim (this is how docs/REVIEW-2026-09.md reproduced the YAML defects). Two options:

- Wrap modules as `(function (WS) { ... })(typeof window !== 'undefined' ? (window.WS = window.WS || {}) : module.exports)`.
- Keep the IIFEs and load them with `new Function('window', src)` from `test/load.js`.

# Requirements

- `test/load.js` that builds a `WS` object from the real source files in dependency order.
- `test/yaml.test.js`, `test/parser.test.js`, `test/ids.test.js`.
- Fixture corpus with round-trip assertions.
- A `npm test`-free invocation (`node --test test/`), documented in the README.

# Implementation Notes

The same loader is reused later by `tools/validate-workspec.js` (see the ID collision proposal), so keep it dependency-free and small.

Decisions taken during implementation (2026-09-04):

- Loader option 2 was chosen: the IIFEs are untouched and `test/load.js` evaluates each file through `node:vm` with its real filename, so stack traces point at the source. `core/model.js` is DOM-free and is loaded too.
- "Content-equal" is defined in `test/helpers.js`: identical after dropping a BOM, normalising CRLF to LF, dropping full-line `#` comments in the front matter, and trimming trailing whitespace per line. Everything else, body included, must match byte for byte. Besides the source form, every fixture is also run as a CRLF variant and a BOM variant, and the second serialize pass must be byte-identical to the first.
- Forms the engine parses but deliberately rewrites (`~`/`null` to empty, single quotes to double, populated flow sequences to block sequences, `>` folding, `|-`) are covered by parse assertions in `test/yaml.test.js`; the fixture corpus only holds files the board must write back unchanged.
- The corpus found one defect on day one: `joinDocument` only stripped leading `\n` from the body, so a CRLF file gained a blank line after the closing fence on every save. Fixed in `utils/yaml.js` (one regex). Left for STORY-000001: the serializer emits `key: ` with a trailing space for null values, and both `joinDocument` and `patchScalarLine` write `\n` into a CRLF file, leaving mixed line endings.
- Node 24 does not accept a bare directory (`node --test test/`); the README documents `node --test` and `node --test "test/*.test.js"` instead. `.gitattributes` marks `test/fixtures/**` as `-text` so the CRLF and BOM fixtures survive checkout with `core.autocrlf=true`.

# Risks

None significant. Keep the browser code path byte-identical if the shim approach is chosen.
