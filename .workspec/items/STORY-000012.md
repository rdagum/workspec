# Summary

SPEC.md section 5 defines `.workspec/archive/` but nothing uses it, and the only removal path is a permanent delete. Add archive, bulk archive and restore.

# Business Context

Done columns fill up; teams want to clear the board without losing history or breaking references.

# Technical Context

`WorkspecFS` needs a move operation (copy then delete is acceptable on the File System Access API, which has no rename). `loadRepository` needs to list `archive/` as a second, read-only item source.

# Requirements

- `moveFile` in the filesystem backend(s).
- Archive, bulk archive and restore mutations in the store.
- Archived view in the board and sidebar.

# Implementation Notes

Keep archived items out of `model.items` so filters, facets and ID generation are unaffected; expose them as `model.archived`.

# Risks

`nextId` must still consider archived IDs to avoid reuse; include archived IDs in the existing-ID scan.
