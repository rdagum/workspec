# Summary

Turn the feature on for this repository: price the three agent models, set per-type budgets, mark the agent users, backfill the runs for the items already shipped while their transcripts still exist, and wire the budget gate and the recording step into the routines that do the work.

# Business Context

The tooling is worthless until this backlog uses it. Backfilling the three shipped items gives the board real numbers on day one, and the transcripts that hold those numbers are pruned after Claude Code's retention period, so this has a deadline.

# Technical Context

Transcripts for the 2026-09-04 sessions are under `~/.claude/projects/c--Users-rdagum-Code-workspec/`; routine runs with the Worktree toggle land under a `…--claude-worktrees-<name>` sibling directory. Those three items were direct commits to `main`, so `ref` is a commit sha, not a pull request. Prices must come from the live price list on the day (load the `claude-api` skill in the session that fills the file) and never from memory or from any document in this repository.

# Requirements

- `config/ai.yaml`, `users.yaml` kinds, backfilled runs, gates-skill text, routine text.

# Implementation Notes

Proposed text for the personal `daily-workspec` skill (outside this repository; the user applies it):

- Step 0, after `select_item.sh`: the selector also skips an item whose `node tools/usage-report.js ID --json` reports `remaining` at or below zero, with the skip reason "over budget"; when the repository has no `tools/usage-report.js`, the gate is skipped.
- Step 6, before `gh pr create`: `node tools/record-usage.js <ID> --from-transcript=<this session> --branch=<branch>` (when the repository ships it), commit as `chore(workspec): record usage for <ID>`. If the session id is not known to the agent, record from the newest transcript in the project directory whose rows carry the run's branch.
- "When the run cannot finish": the usage step runs on this path too, before the draft pull request.
- A new hard rule: never start an item whose budget is spent; open the `[over budget]` draft pull request instead.

# Risks

Filling prices from memory would silently mis-cost every item; the acceptance criterion forbids it for that reason.
