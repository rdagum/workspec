# Summary

Give WorkSpec a model of AI usage: parse `agent.runs` and `agent.budget_usd`, load `config/ai.yaml`, derive cost, roll-ups and budget state, validate the shape, and provide the line-level append that every writer of runs will use. This is the data layer that STORY-001002 (tools) and STORY-001003 (board) build on; it writes nothing on its own.

# Business Context

Items on this board are worked by agents, and the cost of that work is invisible today and unrecoverable once the session transcript is pruned. Recording it on the item makes it visible on the board, checkable by an agent before it starts, and portable with the `.workspec` directory. The design and the rejected alternatives are in `docs/DESIGN-2026-09-ai-usage.md`; the normative text is `SPEC.md` 18.2.

# Technical Context

Follow the shape of `core/allocation.js`: pure functions, issues as `{ file, message, code }` pushed onto the record and onto `model.loadErrors` / `model.warnings`, called from `core/model.js` right after `validateRepository(model)`. Two engine facts matter: decimals parse as strings (`utils/yaml.js` `parseScalar` only turns integers into numbers), so `toNumber` must accept both and derived values are never written; and re-serializing an item changes unrelated lines (quotes, trailing spaces after null keys, comments), so `appendRunText` is a line-level edit in the manner of `appendBlockEntry`, not a `serializeItem` call. Nothing populates per-record warnings today; these are the first, and only the CLI prints them until STORY-001003 renders them in the editor.

# Requirements

- `core/usage.js` with the exports named in the acceptance criteria; DOM-free so it loads in Node.
- `config/ai.yaml` loading in `loadRepository`, using the `parseConfig` pattern of `users.yaml`.
- `users.yaml` `kind` and `model` kept on `model.users`.
- The validation table of `docs/DESIGN-2026-09-ai-usage.md` 3.3, verbatim codes.
- Tests and the round-trip fixture.

# Implementation Notes

Add the module to `index.html` between `core/allocation.js` and `core/model.js`, and to `PURE_MODULES` in `test/load.js` at the same position. `require_usage_from` names a workflow column; "at or after" means its index in `model.workflow` or higher, default the last column. `rollup` needs a visited set. Keep the append text generator small: `stringifyYaml([run])` re-indented by four spaces produces exactly the block that goes under `  runs:`.

# Risks

The first per-record warnings in the codebase: check `collectProblems` in `tools/lib.js` prints them and that the board's error badge ignores them rather than counting them as errors.
