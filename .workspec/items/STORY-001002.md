# Summary

Two zero-dependency Node tools over the model from STORY-001001: `record-usage.js` appends a run to an item — by hand, or imported from a Claude Code session transcript including its subagents — and `usage-report.js` prints roll-ups and one item's budget state. Together they are what an agent runs before and after a session.

# Business Context

An agent cannot read its own usage while it runs; the numbers exist only in the transcript on disk and are pruned after a retention period. The import tool is what turns a transient transcript into a durable fact on the item, and the report is the pre-run budget gate the daily routine needs.

# Technical Context

Reuse `tools/lib.js` (`loadWorkspec`, `parseArgs`, `NodeWorkspecFS`) and `test/load.js` like the existing tools; `parseArgs` accepts only `--flag` and `--key=value`, so the syntax is fixed to that. Transcript facts verified on 2026-09-09 (also in README "Tracking AI usage"): each API response is logged as several rows that repeat the same `message.id` and usage block, so naive summing over-reports several-fold; subagent transcripts live in `<session-id>/subagents/agent-*.jsonl` next to the parent file, with their own model; rows carry `gitBranch` and `cwd`; `<synthetic>` rows carry no usage. Routine runs with the Worktree toggle write to a different project directory (`…--claude-worktrees-<name>`), so session-id lookup must search every project directory whose name starts with the repository's.

# Requirements

- `tools/record-usage.js` with the manual flags and the transcript adapter as specified.
- `tools/usage-report.js` with repository and single-item modes, `--json` and `--strict`.
- A transcript fixture under `test/fixtures/transcripts/` (synthetic, small) with duplicated rows and a `subagents/` directory.
- README and CLAUDE.md command documentation.

# Implementation Notes

Print the appended run in `--dry-run` exactly as it would be inserted. Write the costs the report derives with at most four decimals. Keep all arithmetic in `core/usage.js`; the tools only parse arguments, read files and print.

# Risks

Transcript format is Claude Code's, not WorkSpec's, and may change; keep the adapter in one function with the field names in one place, and make a row without `message.usage` a skip, not a crash.
