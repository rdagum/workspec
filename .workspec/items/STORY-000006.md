# Summary

Only the File System Access backend exists, so the required fallback import mode is missing and Firefox/Safari users get a banner. Define the backend contract explicitly and add an in-memory backend fed by a directory upload with zip export.

# Business Context

PROMPT.md requires a fallback import mode, and a second backend gives the test suite a fast in-memory repository.

# Technical Context

`WorkspecFS` (`core/filesystem.js`) is already the only I/O seam, so a second implementation slots in without touching `core/model.js` or the store. Persisting the native directory handle for quick reopen is a native-backend concern handled by STORY-000009; the contract documentation should say so.

# Requirements

- Contract documentation and a `MemoryFS` implementation.
- Directory upload path and zip export of changed files.
- Cache correctness fix for `exists()` (`core/filesystem.js:86`, `:119`).

# Implementation Notes

A minimal zip writer (store method, CRC-32) is about 150 lines and keeps the no-dependency rule. Keep it in `utils/zip.js`.

# Risks

Two backends double the manual test surface; the in-memory backend must be exercised by the automated suite (STORY-000003).
